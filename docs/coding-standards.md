# コーディング規約

このドキュメントには、設定ファイルや既存コードからは判断できないプロジェクト固有の方針だけを記載する。

## 命名規則

- 頭字語（例: `ID`、`URL`、`HTML`）も通常の単語として扱う。
  - 変数・関数: `userId`、`htmlContent`、`urlPattern`
  - クラス・インターフェース: `UserId`、`HtmlParser`、`UrlValidator`
  - `userID`、`HTMLContent`、`URLPattern`のような表記は使用しない。
- この方針は、`getHtmlUrl()`のように頭字語が連続した場合も単語の境界を明確にするためのものである。

## コメント

- コードから明らかな処理内容ではなく、その実装を選んだ理由や制約を説明する。
- 直感に反する実装やデメリットを受け入れた実装には、その理由を残す。
- 複雑な処理では、必要に応じて処理の流れも補足する。

## 関数の分割

- 行数ではなく、関数が単一の責務を持つかを基準に分割する。
- 設定値や定型処理を、行数を減らす目的だけで別関数や別ファイルへ移さない。
